# AGENTS.md

Personal NixOS flake in `/etc/nixos`, single user (`xjle`), two hosts in `flake.nix`.

| Flake attr | `networking.hostName` | `hw_file` | Hardware |
|---|---|---|---|
| `desktop` | `nixos` (NOT `desktop`) | `nixos` | AMD + NVIDIA |
| `thinkpad` | `thinkpad` | `thinkpad` | Intel |

## Commands

- Rebuild/activate: `sudo nixos-rebuild switch --flake /etc/nixos#desktop` (or `#thinkpad`)
- Validate without activating: `sudo nixos-rebuild build --flake /etc/nixos#desktop`
- Fast eval: `nix eval --raw /etc/nixos#nixosConfigurations.desktop.config.networking.hostName`.
  `--raw` only works for strings; use `--json` for booleans (`...programs.umbriel.enable`).
- Update inputs: `nix flake update`; one input: `nix flake update <name>`
- Agent `sudo` is blocked by permission rules; hand `switch`/activation to the user.
- No CI, tests, lint, or formatter config. `nixfmt` is NOT installed; if needed run
  `nix run nixpkgs#nixfmt-rfc-style -- <file>`.
- The `home-manager` CLI is NOT installed. Home-manager is only used as a NixOS module,
  so all changes (system and home) go through `nixos-rebuild`.

## Critical: flakes only see git-tracked files

New `.nix` files are invisible to `nixos-rebuild --flake` until `git add`ed.

## Root nixpkgs

- `flake.nix` uses a single `nixpkgs` input (`nixos-unstable`); there is no separate
  `nixpkgs-unstable` input.
- All `inputs.*.nixpkgs.follows = "nixpkgs"` and `nixpkgs.lib.nixosSystem` resolve root
  `nixpkgs` from the registry, not from `flake.nix`. On this machine it is the `nixpkgs`
  node in `flake.lock` (currently nixpkgs-unstable).
- Therefore `nix flake update nixpkgs` updates the real package set. Keep the `nixpkgs`
  entry in `flake.lock`.
- To add stable, create an independent input (do NOT set `inputs.nixpkgs.follows`) and
  expose it via an overlay, e.g. `pkgs.stable`. Never mix NixOS modules across releases.
- `system.stateVersion = "26.11"` (NixOS and home-manager) makes unstable the base; a
  26.05 stable base would be a downgrade.

## Layout

- `flake.nix` outputs are built with `flake-parts`; both hosts come from one `mkHost`
  helper sharing the home-manager wiring, with per-host modules passed via `extraModules`.
- `configuration.nix` — shared entrypoint; imports `devices/${hw_file}.nix` plus an
  explicit module list. Modules are NOT auto-discovered: adding a file under
  `modules/` has no effect until it is added to `imports`.
- Desktop-only modules are wired partly in `configuration.nix` (`nvidia`, `games`,
  `tablet`, `obs`, `olama`) and partly in `flake.nix` (`noctalia`, `cachykernel`,
  `umbriel`, plus `inputs.umbriel.nixosModules.default`). `obs.nix` and `olama.nix`
  live directly in `modules/`, not `modules/desktop/`.
- `devices/*.nix` — generated by `nixos-generate-config`; do not edit.
- `home.nix` — home-manager entrypoint; explicit `imports` with a
  `device == "thinkpad"` branch.
- `home-manager/config/` — plain config files copied via `xdg.configFile`; edits only
  reach `~/.config` after a rebuild.

## Three Wayland stacks (desktop only)

- **Niri + Noctalia**: `programs.niri.enable` (`modules/programs.nix`);
  `home-manager/niri.nix` writes `~/.config/niri/config.kdl`, and
  `home-manager/config/niri.kdl` has `spawn-at-startup "noctalia"`.
- **Mango + DankMaterialShell**: `programs.mango.enable = true`; `home-manager/dms.nix`
  imports `inputs.dms` / `inputs.mangowm` and targets `mango-session.target`.
- **Umbriel**: `programs.umbriel.enable = true`; `home-manager/umbriel.nix` imports the
  HM module. Umbriel needs its NixOS module for `umbriel.service` and the login session;
  the HM module alone only installs the package/config. `programs.umbriel.settings` is
  null, so Umbriel writes `~/.config/umbriel/` on first login — setting it in HM would
  block that.
- Desktop default session is Plasma 6 via `lib.mkForce "plasma"` (`modules/services.nix`);
  hyprland and river-classic are off.

## Device branching

- NixOS side: `hw_file` specialArg (`"nixos"` = desktop, `"thinkpad"` = laptop).
- Home-manager side: `device` extraSpecialArg, same values.
- Thinkpad gets foot/fuzzel/firefox and no Umbriel; desktop gets
  kitty/rofi/opencode/helium/games/wine.
- `home-manager/niri.nix` switches its terminal and other settings off `device`.

## Gotchas

- Desktop kernel: `configuration.nix` sets `linuxPackages_zen`, then
  `modules/desktop/cachykernel.nix` `lib.mkForce`s the CachyOS zen4 kernel. Thinkpad
  kernel is set once in `configuration.nix` (`linuxPackages_xanmod`).
- `programs.qylock` is enabled in `configuration.nix` for both hosts, so
  `inputs.qylock.nixosModules.default` is imported in the shared `mkHost` block.
- `devices/thinkpad.nix` generates an invalid empty swap device; `configuration.nix`
  forces `swapDevices = [ ]`.
- Bootloader is limine (`modules/boot.nix`), not systemd-boot/grub. It hardcodes a
  Windows 11 EFI entry, adds `amdgpu` to initrd on both hosts, and uses plymouth theme
  `mac-style`.
- These files are NOT imported — editing them has no effect:
  `modules/searxng.nix`, `modules/desktop/skwd.nix`, `home-manager/zsh.nix`,
  `home-manager/zathura.nix`. The `skwd-wall` flake is still used directly in `home.nix`;
  zathura is installed via nixvim's `extraPackages`.
- `home-manager/opencode.nix` is desktop-only: it copies
  `home-manager/config/opencode/opencode.jsonc` to `~/.config/opencode/` (plain copy,
  needs a rebuild) and adds `uv` plus the numtide substituter. The opencode package
  itself comes from `home.nix` via `llm-agents`.
- `nix flake update` can fail with `insufficient permission for adding an object to
  repository database .git/objects` because `/etc/nixos/.git/objects/e6` is root-owned.
  The user must run `sudo chown -R xjle:users /etc/nixos/.git`; agent sudo is blocked.
