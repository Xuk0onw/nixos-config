# AGENTS.md

Personal NixOS flake in `/etc/nixos`, single user (`xjle`), two hosts in `flake.nix`.

| Flake attr | `networking.hostName` | `hw_file` | Hardware |
|---|---|---|---|
| `desktop` | `nixos` (NOT `desktop`) | `nixos` | AMD + NVIDIA |
| `thinkpad` | `thinkpad` | `thinkpad` | Intel |

## Commands

- Rebuild/activate: `sudo nixos-rebuild switch --flake /etc/nixos#desktop` (or `#thinkpad`)
- Validate without activating: `sudo nixos-rebuild build --flake /etc/nixos#desktop`
- Fast eval check (no build): `nix eval --raw /etc/nixos#nixosConfigurations.desktop.config.networking.hostName`
- Update all inputs: `nix flake update`; one input: `nix flake update <name>`
- No CI, tests, lint, or formatter config. `nixfmt` is NOT installed; if needed run
  `nix run nixpkgs#nixfmt-rfc-style -- <file>`.
- The `home-manager` CLI is NOT installed. Home-manager is only used as a NixOS module,
  so all changes (system and home) go through `nixos-rebuild`.

## Critical: flakes only see git-tracked files

New `.nix` files are invisible to `nixos-rebuild --flake` until `git add`ed.

## Root nixpkgs is implicit

- `flake.nix` declares `nixpkgs-unstable` but nothing references it.
- All `inputs.*.nixpkgs.follows = "nixpkgs"` and `nixpkgs.lib.nixosSystem` resolve root
  `nixpkgs` from the indirect registry, not from `flake.nix`. On this machine it currently
  resolves to `channels.nixos.org/nixpkgs-unstable`.
- Therefore `nix flake update nixpkgs` updates the real package set; updating
  `nixpkgs-unstable` changes nothing the build uses. Keep the `nixpkgs` entry in
  `flake.lock`.
- To add stable, create an independent input (do NOT set `inputs.nixpkgs.follows`) and
  expose it via an overlay, e.g. `pkgs.stable`. Never mix NixOS modules across releases.
- `system.stateVersion = "26.11"` (NixOS and home-manager) makes unstable the base; a
  26.05 stable base would be a downgrade.

## Layout

- `configuration.nix` — shared entrypoint; imports `devices/${hw_file}.nix` plus an
  explicit module list. Modules are NOT auto-discovered: adding a file under
  `modules/` has no effect until it is added to `imports`.
- `modules/` — shared system modules. Desktop-only modules are wired partly in
  `configuration.nix` (`nvidia`, `games`, `tablet`, `obs`, `olama`) and partly in
  `flake.nix` (`noctalia`, `cachykernel`). `obs.nix` and `olama.nix` live directly in
  `modules/`, not `modules/desktop/`.
- `devices/*.nix` — generated by `nixos-generate-config`; do not edit.
- `home.nix` — home-manager entrypoint; explicit `imports` with a
  `device == "thinkpad"` branch.
- `home-manager/config/` — plain config files copied via `xdg.configFile`; edits only
  reach `~/.config` after a rebuild.

## Device branching

- NixOS side: `hw_file` specialArg (`"nixos"` = desktop, `"thinkpad"` = laptop).
- Home-manager side: `device` extraSpecialArg, same values.
- Thinkpad gets foot/fuzzel/firefox; desktop gets kitty/rofi/opencode/helium/games/wine.
- `home-manager/niri.nix` switches its terminal and other settings off `device`.

## Gotchas

- Desktop kernel: `configuration.nix` sets `linuxPackages_zen`, then
  `modules/desktop/cachykernel.nix` `lib.mkForce`s the CachyOS zen4 kernel. Thinkpad
  kernel is set twice to the same `linuxPackages_xanmod` (`configuration.nix` and
  `flake.nix`), so harmless but redundant.
- Bootloader is limine (`modules/boot.nix`), not systemd-boot/grub. It hardcodes a
  Windows 11 EFI entry, adds `amdgpu` to initrd on both hosts, and uses plymouth theme
  `mac-style`.
- Desktop default session is Plasma 6 via `lib.mkForce "plasma"` (`modules/services.nix`);
  niri is enabled while hyprland/mango/river-classic are disabled (`modules/programs.nix`).
  `home-manager/river.nix` and `mango.nix` are still imported, so their configs are written
  even though those sessions are off.
- These files are NOT imported — editing them has no effect:
  `modules/searxng.nix`, `modules/desktop/skwd.nix`, `home-manager/zsh.nix`,
  `home-manager/zathura.nix`. The `skwd-wall` flake is still used directly in `home.nix`;
  zathura is installed via nixvim's `extraPackages`.
- `home-manager/opencode.nix` is desktop-only: it copies
  `home-manager/config/opencode/opencode.jsonc` to `~/.config/opencode/` (plain copy,
  needs a rebuild) and adds uv/biome plus the numtide substituter. The opencode package
  itself comes from `home.nix` via `llm-agents`.
